# Independent mature-V2 acquisition permissions

For smart-research V2 targets, `DECODO` / `DIRECT_PROHIBITED_DECODO_PERMITTED`
selects a useful, reviewed destination only when Direct is explicitly OFF and
Decodo explicitly ON. Tavily remains discovery-only and is not required for a
known destination. Direct ON retains Direct preference and the existing
`CONDITIONAL_DECODO` failure-proof fallback. Permission is never a requirement
to spend: retained sufficiency and reuse precede acquisition.

The independent path requires an existing admitted market (the existing Decodo
runner is country-bound). Marketless catalog targets do not gain a synthetic
market or pricing target. Unknown provider ownership still requires review.

The controller rechecks execution eligibility, calls the normal destination
classifier, persists the acquisition reservation and dispatched action, then
calls the existing Decodo binding. The binding records
`INDEPENDENT_DECODO_ADMITTED`; fallback records `GEO_ESCALATION_ELIGIBLE`.
No Direct failure is fabricated. Decodo's existing zero-retry child acquisition
retains robots policy, bracket geo proof, paid authorization, request/byte/cost
reservations, source journals, interpretation and targeted verification.
Actual network requests remain charged as DECODO by the mature lifecycle host.

Acquisition reservations/outcomes and routing memory suppress repeated resource
attempts. Interrupted dispatched actions remain reconciliation-required;
this change introduces no recovery or automatic retry. Results pass the existing
quarantine wrapper and retained pricing eligibility. Search snippets grant no
provider evidence. The normal verifier, positive recurring-provider-price rule,
user pricing, service admission and lifecycle scheduling are unchanged.

Readiness remains configuration-derived. The UI explains controlled acquisition
rather than describing Decodo as fallback-only; no credentials, authorization
limits or readiness values are changed.
