# Durable canonical price research learning

Canonical `PRICE_RESEARCH` first learned `providerPricingRouteMemory` within a batch. The starting commit for this phase already persisted G1-proven routes from completed canonical batches, but known-service single jobs only loaded that index, and documented method outcomes were not durable. The existing V2 hybrid resource index serves autonomous provider authority review and has a different admission contract.

The versioned `V2_PROVIDER_PRICING_ROUTE_MEMORY_V1` index lives at `.savlivo/research-v2/storage/provider-pricing-routes-v1.json` on the existing persistent research disk. Both canonical batches and completed known-service single jobs publish to this index. A later job loads only rows for its selected services. Country route candidates must still come from that target's supported provider route pattern. Loading a route never loads an old price, receipt, Truth result, or provider body into the new target.

Successful routing is published only after the exact retained body, SHA-256, original acquisition journal, official source classification, service and market identity, G1 country receipt, and source-bound V3 price propositions agree. The route index contains a proof reference; the content-addressed proof body is in the same permanent storage namespace. Known-service single jobs validate their own original journal and bracketed country checks without changing the separate Verified reconciliation contract.

The same sealed index also has bounded `methodOutcomes` for attempted learned or supported country-route URLs, including Direct reads and Decodo acquisitions. Each row records job, checkpoint, service, market, public URL, method, outcome, timestamp, checkpoint hash, optional source hash, and known request/byte counters. Actual billed cost is `null` because the checkpoint does not record a bill. The index does not contain body text, plan prices, receipts, raw queries, or URL parameters that might carry secrets or personal data. If the parser explicitly records native structured facts, that strategy is noted; otherwise parser strategy remains unknown. A successful method row additionally requires a matching validated route origin. An unsuccessful attempt means no durable success proof from that attempt; it does not assert that the provider has no price.

Method failures lower ordering only for the exact service, market, and URL, for at most seven days. A newer success cancels the penalty. The batch-local failure guard still prevents repeated acquisition in one job, while the loader resets that transient counter for a new job. Normal discovery remains available. The store is capped at 10,000 route entries and 4,096 recent method outcomes; these bounds limit retained operational observations, not provider evidence or job artifacts.

Publication uses an exclusive lock, a same-directory pending file, `fsync`, and atomic rename. A partial pending file is ignored. Publication is idempotent by source origin and method observation ID. There is no database migration, startup write, production backfill, or garbage collection in this phase. Existing jobs keep their original target and evidence snapshots. The original acquired source and G1 receipt remain required for every new market acquisition, and V3 Truth and Verified admission are unchanged.
