# V2 capability audit for V3 provider research

The audited V2 flow is `live/runner.mjs` → reviewed provider/source inventory → acquisition → detached interpretation/verification → coverage finalization → optional online discovery. `open-web-discovery.mjs` also provides a persisted, bounded lead/search/read scheduler. Neither its verification nor its retained confidence/completion decisions belongs in V3.

Locations below are relative to `services/api/src/research-v2/`. A = general research mechanism, B = advisory discovery signal, C = incompatible truth assumption, D = redundant or outside this milestone. All adopted mechanisms are reimplemented in V3; no V2 runtime import is needed.

## Additional V2 boundaries inspected

`live/frontier-inventory.mjs` appends a first discovered source only after exact reviewed domain/source binding and may skip covered catalog services (A for binding/provenance; D for catalog coverage policy). `intelligence/price-entry-intent.mjs` uses up to 2 MiB source, 2,000 controls and 50,000 tokens; accessible labels/structure are A/B, but its large multilingual term list, excluded support routes and corroborated CTA gates are not imported. `code-dataflow/module-resources.mjs` and `chunk-resources.mjs` statically inspect source-owned script/import/manifest references with exact parent hashes, finite depth/work/token/entry bounds and no execution (A engineering capability, deliberately not adopted here: module/configurator resource interpretation is a separate subsystem, not ordinary provider page navigation). `offline-recovery/provider-market.mjs` combines canonical routes, document locales and source content into V2 market-proof patterns (C: none imported). Broad search across V2 found no sitemap implementation to port.

## Operational comparison

V2 frontiers commonly bound 50 candidates/target, 512/provider, 2,000 extracted links, depth 2–3, 40 retained navigation candidates and widths of 2. Its online stage uses at most three acquisitions/target, 24 requests/target, 8 MiB/target; open-web discovery uses bounded searches, reads and leads. These are engineering precedents, not values or proof requirements to copy. V3 already has stronger acquisition (8/16 MiB encoded/decoded, bounded decompression/redirects/robots, verified geography), independently bounded semantic units, reservations and deterministic reconstruction.

Strengths selected: source-owned structure, provenance, finite query families, bounded broad frontiers and history-sensitive routing. Weaknesses rejected: catalog coupling, language tables, confidence completion, hard foreign-locale exclusion, Direct-first gates and URL-only context deduplication. V2 has no adequate automatic cross-domain ownership proof; V3 must require reviewed authority configuration for unrelated domains and explicit reviewed namespace permission for subdomains.

The implementation scope is discovery, navigation, planner scheduling and checkpointed research state. Truth/evidence/semantic interpretation modules remain unchanged. Candidate scores, metadata and advisory outputs can only select an acquisition.
